# Darwin Home Manager runtime review

## 1. Is runtime service wiring complete and reproducible?

### Takeaway

The Home Manager import structure and most package wrappers are coherent. The most important service defect is skhd: the declarative instance currently loses its PID lock to an independently installed instance, and its own launchd environment is insufficient for the configured commands. These are separate problems; removing the competing instance alone would not complete the repair.

### Cited Findings

**R1 — P1, observed live: two skhd service owners; managed instance repeatedly fails.**

- Repository enables Home Manager's skhd service at `darwin/home/services/skhd.nix:34-36`. The installed HM module creates `org.nix-community.home.skhd` with `KeepAlive=true`, `RunAtLoad=true`, and the package executable, at `/nix/store/0ql2valpm8n9qqavz2bmkg9f4q8s5f59-source/modules/services/skhd.nix:61-70`. A second on-disk LaunchAgent, `~/Library/LaunchAgents/com.koekeishiya.skhd.plist:5-9`, also launches skhd. [Repository source](file:///Users/martin/nix/darwin/home/services/skhd.nix#L34), [HM source](file:///nix/store/0ql2valpm8n9qqavz2bmkg9f4q8s5f59-source/modules/services/skhd.nix#L61), [managed plist](file:///Users/martin/Library/LaunchAgents/org.nix-community.home.skhd.plist#L5), [competing plist](file:///Users/martin/Library/LaunchAgents/com.koekeishiya.skhd.plist#L5).
- Read-only `launchctl print gui/$(id -u)/org.nix-community.home.skhd` reported `state = spawn scheduled`, `last exit code = 1`; the same query for `com.koekeishiya.skhd` reported `state = running`, PID 822. The managed error log's tail repeatedly says `skhd: could not lock pid-file! abort..`. A streamed count found 1,213,735 such lines, first at line 3 and last at line 1,239,801 during inspection. These are accumulated historical errors, not a measured current rate or a date-bounded count. Upstream 0.3.9 uses the same per-user `/tmp/skhd_%s.pid` and exits on lock failure. [Error log](file:///Users/martin/Library/Logs/skhd/skhd.err.log#L1239801), [upstream lock implementation](https://github.com/koekeishiya/skhd/blob/v0.3.9/src/skhd.c).
- Trigger: login or a service restart while both agents are installed. Impact: the Nix-managed service does not own the running hotkey process; KeepAlive repeatedly retries and accumulates errors. The competing service also captures a long mutable PATH including Homebrew, old OrbStack, and shell-plugin directories. Repair direction: deliberately consolidate service ownership, then fix R2 before relying on the managed instance. No services were stopped/reloaded/changed in this review. [Competing service environment](file:///Users/martin/Library/LaunchAgents/com.koekeishiya.skhd.plist#L11), [managed service settings](file:///nix/store/0ql2valpm8n9qqavz2bmkg9f4q8s5f59-source/modules/services/skhd.nix#L61).

**R2 — P1/P2, reproduced with read-only shell simulations: skhd needs an explicit command PATH and zsh.**

- Nearly every binding invokes unqualified `yabai`; several invoke `jq`, `skhd`, or `sketchybar`. The repository supplies no launchd environment override. HM's skhd module sets no PATH/SHELL, and launchd's `EnvironmentVariables` option defaults to null. Actual `launchctl print` showed the managed service's default PATH as `/usr/bin:/bin:/usr/sbin:/sbin`; no SHELL appeared, and read-only `launchctl getenv SHELL` returned empty. Under that PATH, `command -v yabai`, `sketchybar`, and `skhd` all failed; `/usr/bin/jq` did exist on this machine. [Bindings](file:///Users/martin/nix/darwin/home/services/skhd.nix#L15), [more bindings](file:///Users/martin/nix/darwin/home/services/skhd.nix#L44), [HM implementation](file:///nix/store/0ql2valpm8n9qqavz2bmkg9f4q8s5f59-source/modules/services/skhd.nix#L61), [null environment default](file:///nix/store/0ql2valpm8n9qqavz2bmkg9f4q8s5f59-source/modules/launchd/launchd.nix#L298).
- The generated space binding at `skhd.nix:15` uses zsh-specific `$SPACES[1]` expansion and 1-based indexing. Upstream skhd 0.3.9 invokes `$SHELL -c`, falling back to `/bin/bash` if SHELL is absent. With stubbed `yabai` returning space IDs `11 12 13 14` and stubbed `jq`, the exact expression under `/bin/bash -c` passed `11[1]` as the space ID; `/bin/zsh -c` correctly passed `11`. No real yabai command ran. [Binding generator](file:///Users/martin/nix/darwin/home/services/skhd.nix#L7), [upstream init_shell/fork_and_exec](https://github.com/koekeishiya/skhd/blob/v0.3.9/src/hotkey.c).
- Trigger: managed service on a clean login with ordinary launchd environment, or a caller explicitly selecting Bash. Repair direction: give this service an explicit Nix zsh SHELL and `lib.makeBinPath` of its command dependencies plus Darwin system tools, or package action scripts with explicit interpreter and dependencies. Absolute executable references alone do not fix the array syntax. The current failure to start in R1 prevents an end-to-end hotkey test; R2's command lookup and parsing defects were tested independently. [Service configuration](file:///Users/martin/nix/darwin/home/services/skhd.nix#L34).

**Positive wiring and boundaries inspected.**

- `home.nix:2-6` imports packages/programs/services, and its Darwin application strategy explicitly disables linkApps and enables copyApps. All program files listed in `programs/default.nix:6-18` are imported, and all four service files are imported in `services/default.nix:2-6`; no orphan module was found within this scope. [Home](file:///Users/martin/nix/darwin/home/home.nix#L2), [program imports](file:///Users/martin/nix/darwin/home/programs/default.nix#L6), [service imports](file:///Users/martin/nix/darwin/home/services/default.nix#L2).
- The OSS workflow has a meaningful module boundary: configurable package/root/consumerRoots, session variables, activation mkdir, a Darwin-only pruner, and an assertion requiring the base program. The pruner explicitly supplies its environment and executable, unlike skhd. Its weekly schedule is Monday 09:00, RunAtLoad=false, `--yes --min-age 7d`. These good wiring choices do not mitigate the deletion-eligibility defects in R3. [Base module](file:///Users/martin/nix/darwin/home/programs/oss-references.nix#L20), [pruner](file:///Users/martin/nix/darwin/home/services/oss-references-pruner.nix#L27).
- SSH deliberately uses Apple's client (`package=null`) and Keychain support; Git's launchd agent uses absolute `/usr/bin/ssh-add --apple-load-keychain -q`. Local host config is included before managed settings. This is internally consistent, but key material and Keychain enrollment remain external state. [SSH](file:///Users/martin/nix/darwin/home/programs/ssh.nix#L3), [Git signing/agent](file:///Users/martin/nix/darwin/home/programs/git.nix#L13), [agent](file:///Users/martin/nix/darwin/home/programs/git.nix#L126).
- The ff2mpv native host is installed in the Darwin Mozilla NativeMessagingHosts directory and uses an absolute store launcher. Its launcher adds `/etc/profiles/per-user/$(id -un)/bin` so GUI Firefox can locate mpv. This is coherent for the current system-profile layout, though less self-contained than referencing the configured mpv package directly. [ff2mpv wiring](file:///Users/martin/nix/darwin/home/programs/mpv.nix#L15).
- Sketchybar's deployed interpreter and C module both use Lua 5.5. The live C module link resolved to `...-lua5.5-sbarLua-0-unstable-2026-03-06/lib/lua/5.5/sketchybar.so`, and the inspected nixpkgs recipe builds with lua55Packages. No current ABI mismatch was found. [Deployment](file:///Users/martin/nix/darwin/home/services/sketchybar.nix#L13), [inspected recipe](file:///nix/store/ffj7pg45lgrjix75bml2fhsccw512js1-source/pkgs/by-name/sb/sbarlua/package.nix#L8).

### Inferences

- Extensibility would improve by moving skhd actions into small `writeShellApplication`/explicit-zsh packages, exposing shared space-count/interface/font settings, and making service ownership unambiguous. Existing `oss-references` and `oxker` wrappers are useful local patterns. [skhd](file:///Users/martin/nix/darwin/home/services/skhd.nix#L7), [OSS wrapper](file:///Users/martin/nix/darwin/home/programs/oss-references.nix#L9), [oxker wrapper](file:///Users/martin/nix/darwin/home/programs/oxker.nix#L7).
- The ff2mpv per-user profile assumption would need revisiting if this home configuration is reused without system `useUserPackages`; a store-path dependency on `config.programs.mpv.package` would express the actual runtime dependency. This is a portability observation, not a reproduced current failure. [launcher](file:///Users/martin/nix/darwin/home/programs/mpv.nix#L18).

### Gaps

- No build, full flake evaluation, activation, Accessibility permission check, hotkey press, window movement, or service lifecycle operation was performed. Whether every pinned Nix package/extension attribute evaluates/builds is the system/flake reviewer's concern.
- Yabai's current SIP/native space-focus capabilities were not independently verified. Do **not** infer that every `space --focus` binding is broken solely from `enableScriptingAddition=false`; the installed version is 7.1.25, and older guidance can be stale. The concrete skhd defects above do not depend on that question.

## 2. Are custom scripts safe and correct under their advertised workflows?

### Takeaway

The OSS-reference pruner's fail-open discovery can delete a still-used clone, and `git sweep` does not actually exclude the default branch. Syntax and ShellCheck pass, illustrating why behavioral fixtures matter more than syntax-only validation for these scripts.

### Cited Findings

**R3 — P1, selection algorithm reproduced in memory: prune treats incomplete discovery or a descendant link as an orphan.**

- `oss-ref.sh:202-209` silently skips nonexistent consumer roots and discards `find`/`readlink` errors (`2>/dev/null`, process substitution). There is no propagated failure flag before deletion. `:223` checks only an exact match of the resolved symlink target against the clone directory, so a valid consumer link to `repo@v1/src` or `repo@v1/README.md` does not protect the parent clone. `:246-248` executes `rm -rf` with `--yes`; the enabled weekly agent always passes `--yes`. [Scan](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L194), [match/deletion](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L217), [schedule](file:///Users/martin/nix/darwin/home/services/oss-references-pruner.nix#L42).
- Read-only reproduction: source the actual script into Nix Bash, set ROOT and CONSUMER_ROOTS to the existing repository, override `find` in memory to emit one candidate equal to ROOT and one resolved target equal to `ROOT/darwin`, then run `cmd_prune --dry-run`. Output was `nix  orphan`, status 0. A second fixture emitted the same candidate but made the consumer-scan `find` return 1; output was again `nix  orphan`, status 0, no error. These mocks isolate the actual matching/error-handling algorithm without creating links, cloning, deleting, or touching user state. [Executed function](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L153).
- Trigger A: consumer directory is unavailable, moved, permission-denied, or partially unreadable at Monday's scan, and an older-than-7-days candidate is still in use there. Trigger B: only a subdirectory/file of a shared clone is linked into a consumer tree. Trigger C: a valid consumer was created outside the configured roots—`add` accepts arbitrary link paths but neither registers nor validates them against `consumerRoots`. Age is directory mtime, not last use, so ongoing reads do not reset protection. This is a concrete algorithmic issue; no actual deletion/data loss was observed. [add accepts arbitrary path](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L92), [default roots](file:///Users/martin/nix/darwin/home/programs/oss-references.nix#L33), [mtime check](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L227).
- Repair direction: refuse destructive pruning on incomplete discovery, normalize resolved targets to their containing managed clone, and either register consumers or enforce/document the supported consumer scope at `add`. Keep dry-run reporting, but include explicit scan failures. Use a genuine deletion fixture only in a disposable test directory when implementation is authorized. [prune implementation](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L153).

**R4 — P2, reproduced filter: `git sweep` passes the protected default branch to deletion.**

- Alias `git.nix:45` uses `grep -E -v ' $(git defaultBranch)$'`: single quotes suppress command substitution, and the resulting text is also interpreted as a regular expression. The exclusion does not match ordinary branch names. A read-only pipeline with input `  main`, `* feature`, `  merged` returned all three lines unchanged. Nothing invoked `git branch -d`. [Alias](file:///Users/martin/nix/darwin/home/programs/git.nix#L44).
- Trigger: run `git sweep` while on a feature branch and the local default branch is deletable under Git's merged-branch rules. The default branch remains in the list; the current branch's `*` marker is also passed as an argument by xargs. Git may delete eligible branches and then return failure for current/nonexistent names, preventing the `&& git remote prune origin` tail. This is local branch-reference loss, not demonstrated loss of committed objects. Repair: use `for-each-ref --format='%(refname:short)'`, explicitly compare names against the default and current branch, and pass names robustly. [Full alias](file:///Users/martin/nix/darwin/home/programs/git.nix#L45).
- Related P3 portability bug: `defaultBranch` uses `cut -d'/' -f4`, truncating a legitimate `refs/remotes/origin/release/stable` to `release`; both `m` and `sweep` depend on it. This follows directly from the string operation; no repository refs were changed. [defaultBranch](file:///Users/martin/nix/darwin/home/programs/git.nix#L42), [m](file:///Users/martin/nix/darwin/home/programs/git.nix#L55).

**R5 — P2/P3, static defect scenarios: OSS add has poor failure recovery/diagnostics.**

- Clone stderr is redirected into a temporary file, but all failure exits at `oss-ref.sh:128-131` discard it via the trap at `:120` without printing its contents. Trigger: network/authentication failure, invalid SHA, missing repository. Result: a failed `oss-ref add` can produce no explanatory error. This was source-traced, not reproduced with a real network failure. [diagnostics/trap](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L115), [failure exits](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L122).
- `add` refuses every existing clone target (`:108-111`), including a valid already-cloned URL/version requested for a second consumer. It publishes the clone and clears cleanup at `:136-138` **before** creating the consumer link (`:141-142`). Trigger: link creation fails, or another project wants the same version. Retrying through `add` then reports `already exists`; recovery/reuse requires manual linking/removal. If the provided symlink path is an existing real directory, GNU `ln -sfn` creates a child link rather than replacing the directory, despite printing `symlink_path -> target`. Recommend validating destination type, supporting verified reuse, and surfacing partial success. These are source-derived cases, not filesystem-mutating tests. [collision check](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L103), [publication/linking](file:///Users/martin/nix/darwin/home/programs/oss-ref.sh#L135).

**R6 — P3, inferred interruption/concurrency risk: OMO profile switcher temporary-file handling.**

- Both symlink-selection branches reuse the fixed `~/.omo/.omo.jsonc.tmp` with plain `ln -s`, then `mv -f`, with no EXIT cleanup. Interruption between those two commands leaves a stale file; later switches fail under `set -e`. Concurrent switches also contend for that name. The `default` branch removes the active selection before copying the replacement; a copy failure leaves it missing. Recommend a unique sibling temp path, cleanup trap, and atomic rename for both paths. This is generic shell filesystem reasoning, not a claim about OpenCode plugin internals; no profile was switched. [switcher](file:///Users/martin/nix/darwin/home/programs/opencode/activate-oh-my-openagent-profile.sh#L28), [fixed temp](file:///Users/martin/nix/darwin/home/programs/opencode/activate-oh-my-openagent-profile.sh#L46).

- `nix-instantiate --parse` succeeded for all 20 Nix files under `darwin/home`; `bash -n` and installed ShellCheck both passed the two standalone `.sh` files; `zsh -n` passed `p10k.zsh`; Lua 5.5.1 `loadfile` syntax checks passed all 15 Lua files. Three OMO JSONC files parsed after removing full-line comments and each set `[opencode].codegraph.auto_init=false`. These are parser/static results, not activation or app-behavior guarantees. ### Inferences

- The best small future test surface is mocked/directory-fixture pruning and shell-action parsing: unreadable/missing consumer roots, descendant symlinks, same-version reuse, directory destination, stale profile temp, and branch names containing `/`. ## 3. Do Sketchybar and application settings behave consistently and remain maintainable?

### Takeaway

Sketchybar has a reproducible low-throughput callback exception and reversed RX/TX labels. Most application definitions are conventional; lower-priority inconsistencies concern configurable paths, declared command dependencies, and deliberately mutable application state rather than demonstrated app-wide failures.

### Cited Findings

**R7 — P2, reproduced on configured Lua 5.5: network callback errors on fractional low rates.**

- `network.lua:47,50` divides integer byte-counter deltas by two; an odd delta yields a fractional number. `format_bytes` passes values below 1000 to `string.format("%4dB", bytes)` without rounding at `:11`. Lua 5.5 rejects a nonintegral value for `%d`. [formatter](file:///Users/martin/nix/darwin/home/sketchybar/items/network.lua#L9), [rate calculation](file:///Users/martin/nix/darwin/home/sketchybar/items/network.lua#L43).
- Reproduction used the actual `items/network.lua` with an in-memory `sbar` stub (no daemon calls): first sample `100 200`, second `101 202`; first update printed `↑   0B ↓   0B`, second callback failed with `network.lua:11: bad argument #2 to 'format' (number has no integer representation)`. Trigger: either counter changes by an odd 1–1999 bytes between samples. Impact proven: that callback fails and does not set the label. Whether the C event loop survives/logs the error was not tested; do not claim the whole bar crashes. Fix direction: round/floor the byte-rate branch or use a floating-point format. [callback](file:///Users/martin/nix/darwin/home/sketchybar/items/network.lua#L35).

**R8 — P2, confirmed against local Darwin netstat: network directions are reversed.**

- The script reads `$7, $10` from `netstat -ibn`, names them `tx, rx`, and displays them next to up/down arrows respectively. Actual local header was `Name Mtu Network Address Ipkts Ierrs Ibytes Opkts Oerrs Obytes Coll`: field 7 is inbound bytes and field 10 outbound. Thus download is shown as upload and upload as download. Correct variable assignment/order. [parsing](file:///Users/martin/nix/darwin/home/sketchybar/items/network.lua#L36), [display](file:///Users/martin/nix/darwin/home/sketchybar/items/network.lua#L58), [arrow definitions](file:///Users/martin/nix/darwin/home/sketchybar/icons.lua#L64).
- Further source-derived limitations: both network and Wi-Fi hardcode en0; rate calculation assumes precisely two elapsed seconds even after hidden-bar pauses, forced updates, sleep, or delayed callbacks. Defaults use `updates="when_shown"`. Trigger: Ethernet/another active interface, or hiding/revealing the bar; the metric can represent the wrong interface or wrong time interval. Parameterize/detect the intended interface and measure elapsed time, resetting counters after discontinuities. These are inferred scenarios, not live interface/sleep tests. [network](file:///Users/martin/nix/darwin/home/sketchybar/items/network.lua#L36), [Wi-Fi](file:///Users/martin/nix/darwin/home/sketchybar/items/wifi.lua#L22), [update default](file:///Users/martin/nix/darwin/home/sketchybar/default.lua#L5).

**R9 — P3, dependency mismatch observed: `pn` aliases an undeclared/unavailable pnpm.**

- Zsh defines `pn = "pnpm"` at `zsh.nix:99`, but `packages.nix` installs Node 22 and Bun without pnpm, and none of the imported home program modules declares it. `shutil.which("pnpm")` in the review environment returned None. Trigger: running `pn` outside a project environment that supplies pnpm. Recommendation: declare pnpm if this is intended as a global workflow, otherwise document the project prerequisite. This does not imply project-level devenv/direnv use is broken. [alias](file:///Users/martin/nix/darwin/home/programs/zsh.nix#L96), [packages](file:///Users/martin/nix/darwin/home/packages.nix#L6), [direnv](file:///Users/martin/nix/darwin/home/programs/default.nix#L57).
